# 批量扫描

## 何时使用

- 「帮我扫一批股票，就这几只：XXX、XXX、XXX」
- 「批量分析这些票，看哪个最值得盯」
- 「这几只哪个好？一起出一条对比」
- 「一起看一下这几只，做个排序」
- 「把它们的事件影响批量跑一遍」
- 「对这批票做个因果结构图 / 相关性传导」

（单只标的就用单标的技能，不要为了省事把 1 只票套批量流程——批量调用更慢也更贵。）

## 轻问 vs 深问（成本控制）

**轻问（1-2 个工具，分钟级）**
只想「哪只更突出」时：走**一条**链路即可。
- 看事件冲击 → `causal-event_study_batch`（批量事件研究，一次出 CAR + 显著性）
- 看未来走势 → `kronos-forecast_batch`（批量 K 线预测，异步）
- 看谁带动谁 → `causal-learn_graph`（多标的因果图）

**深问（完整链路 + 结构化报告）**
三条链路串联：事件 → 结构 → 预测，最后按维度排序出一张主表。
最贵的一步：**`kronos-forecast_batch`（批量预测）**——它内部按 `sample_count` 条采样做多条路径，样本数 × 标的数 = 实际推理次数，是整条链路的成本大头；其次是 `causal-event_study_batch`（每只标的都要跑市场模型回归 + 检验）。

**成本控制规则**：先跑便宜的事件研究筛掉一半，只对剩下的票跑预测，不要一上来就全量预测。

## 工具链

### 第 0 步：收集输入（必须由用户提供或用数据源取得）
- 标的清单：代码列表，注意规范写法（如 `sh600519`、`sz300308`、`002371`）。
- K 线数据 `klines`：**工具不会自己找数据**，必须来自以下之一——(a) 用户粘贴/上传的 OHLCV；(b) 本地行情库/接口导出（腾讯行情、mootdx、东财等数据源取日线）；(c) 系统内已有的行情快照。
- 每条 K 线格式：`{timestamps/open/high/low/close/volume/amount?}`（事件研究用 `{date, close}` 即可）。
- 若用户只给了代码没有数据：先说明「需要日线数据才能算」，并告知你从哪个数据源取，不要凭空编造价格。

### 第 1 步：事件类——批量事件研究 `causal-event_study_batch`
- 传参：`events`（数组，必填），每项：
  - `event_id`（自定编号，便于回读）
  - `symbol`（标的代码）
  - `event_date`（`YYYY-MM-DD`，非交易日会自动取最近交易日）
  - `klines`（该标的日线，按日期升序）
  - 可选 `benchmark`（指数日线，与 klines 对齐；缺失按零收益处理）
  - 可选 `sector_benchmark`（板块基准，提供后启用市场+板块双因子模型）
- 可选 `timeout`（子进程超时秒数，默认 120）。
- 返回（每项）：`car_1d / car_3d / car_5d / car_pre1d`、`alpha`、`beta_market`、`t_stat`、`p_value`、`is_significant`、`direction`、`impact_score`、`confidence`、`status`（非 `ok` 时其余为零值占位，要标注为无效）。
- **耗时提醒**：这是**同步**调用（内部起子进程），不是 job_id 模式。标的很多时**拆成 5-10 只一批**分别调用，避免单次超时；超过 20 只就分批 + 告知用户预计几分钟。

### 第 2 步：结构类——多标的因果图 `causal-learn_graph`
- 传参：`data` = `{columns: [标的代码...], rows: [[数值...], ...], dates?: [...]}`，`rows` 按时间升序，建议用**收益率**（原始价格会得到伪相关）。
- 可选 `method`：`pc`（默认，偏相关 + Fisher z 检验）或 `notears`；可选 `alpha`（默认 0.05，条件独立检验显著性）。
- 返回：`edges`（`from / to / weight / direction`）、`nodes`、`method`、`metrics`（`n_edges`、`sparsity`、`avg_weight`）。
- 注意：`direction` 是统计上的方向性判断，**不等于**业务因果关系，报告里要注明。

### 第 3 步：预测类——批量 K 线预测 `kronos-forecast_batch`
- **这是重任务，异步**：先提交拿 `job_id`，再用 **`job_status`（job_id）** 轮询，不要傻等。
- 传参：`series_list`（数组，必填），每项 `{id, klines}`（`klines` 格式同第 0 步）；`pred_len`（必填，预测 K 线根数 ≥ 1）。
- 可选：`lookback`（回看长度，默认=输入长度，上限 512）、`sample_count`（并行采样条数，默认 5，**直接决定耗时与费用**）、`T`（默认 1.0）、`top_p`（默认 0.9）、`future_timestamps`（预测轴时间戳，长度 ≥ pred_len，不给则按中位间隔顺延）、`model`。
- 逐项容错：单项失败不会拖垮整批，结果项带 `error` 字段——报告里要单独列出失败项，不要当成 0 收益。
- 返回每项：`summary`（方向/预期收益/预测波动率）+ `predictions`（预测 K 线）。
- **并发/耗时提醒**：耗时 ≈ 标的数 × `sample_count` × `pred_len`。超过 10 只或 `pred_len` > 20 时，先降 `sample_count` 试跑，或分批提交多个 job 并行，然后逐个 `job_status` 轮询。
- **口径声明**：预测是模型输出，非承诺（见「合规边界」）。

### 第 4 步：汇总排序
把三张结果表按统一维度合并成一张主表：
- 默认排序：事件类按 `|car_1d|` 或 `p_value` 显著性降序；预测类按 `expected_return_pct` 降序。
- 每行保留原始指标 + 数据充分度（K 线根数、`status` 是否 ok），缺失或失败的行单独放「数据不足」区。

## 输出格式

Agent 输出契约（按此小节顺序，别自由发挥）：

1. **扫描范围**：标的数量、代码列表、数据窗口（起止日期）、K 线来源、缺失标的。
2. **主表（一张，可排序）**，列固定为：
   `排名 | 代码 | 事件CAR1d | CAR3d | p值 | 是否显著 | 方向 | 因果图入/出度 | 预期收益(%) | 预测波动率 | 置信度 | 状态`
   （某链路没跑就留空并注明「未跑」，不要填 0 冒充。）
3. **分组结论**：显著事件冲击的标的、图中枢纽节点（连接度高的）、预测方向一致的标的，各 1-2 句纯描述。
4. **一致性/矛盾提示**：三条链路结论互相矛盾时明确指出（如事件显著为正但预测向下）。
5. **数据与模型声明**：数据来源、K 线根数、模型版本、`sample_count`/`pred_len` 等参数，以及「模型输出，非承诺」。
6. **失败与限制**：`job_id` 及完成状态、报错项、样本过短的标的。

排序默认规则要在报告里写明（按 |CAR1d| 还是按预期收益），方便用户要求换排序。

## 合规边界

- 只输出**统计计算结果与客观描述**：CAR、t 值、p 值、显著性、相关系数、模型预测值、方向一致性等。
- **不输出**：买入/卖出/加仓/减仓建议，目标价，仓位建议，「必涨/稳赚」类判断，收益承诺。
- Kronos / ML 因子等模型输出必须标注「**模型输出，非承诺**」，并同时给出波动率或离散度，说明置信度含义。
- 因果图边、Granger/传递熵等是统计关系，不得表述为业务上已证实的因果关系；`refute` 类反驳等级如果没跑，就不要声称稳健。
- 不给投资决策背书；结尾提示用户自行判断并注意风险。

## 常见问题

1. **一次塞太多只票 → 超时或拖垮整批。** 事件研究拆 5-10 只一批；批量预测按 `sample_count` 控制成本，先小样本试跑再放量；批量预测务必用 `job_id` + `job_status` 轮询，别在一个调用里死等。
2. **只有代码没有 K 线。** 工具不抓行情，必须由用户提供或从本地数据源取；缺数据就说缺，不要用编造的价格跑出「看起来合理」的结果。样本不足（如事件研究估计窗需要历史 K 线、预测至少需要若干根）要直接标注为无效。
3. **忘看 `status` 和 `error` 字段。** 事件研究 `status != ok` 时返回的是零值占位，批量预测单项失败带 `error`——把这些当成「无数据」，绝不能混进排序里当真结果。
