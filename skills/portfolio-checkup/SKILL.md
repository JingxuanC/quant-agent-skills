# 持仓体检

## 何时使用

命中以下任一话术（大致意思即可，不必逐字相同）：

- 我的持仓有风险吗？
- 仓位重不重 / 是不是太集中了？
- 帮我看看持仓。
- 我这些票安全吗？
- 手里这几只票会不会一起跌？
- 帮我把持仓做个风险体检。

不适用：用户还没买、在问「买什么」——那是选股任务；用户明确要下单——那是交易任务，必须走你自己的交易风控流程。

## 轻问 vs 深问（成本控制）

**轻问**（用户只是随口一问、或只报了 1-2 只票）
- 只跑 1-2 个工具：通常 `factor-miner-regime_detect`（确认市场状态）+ `factor-miner-vol_forecast`（看波动率）。
- 输出 3-5 行结论即可，不做完整报告。

**深问**（用户贴了完整持仓、明确说「体检」「评估风险」）
- 走完整链路：regime → vol_forecast（逐票）→ portfolio_optimize（组合）→ 结构化报告。

**哪一步最贵**
- 最贵的是 `factor-miner-portfolio_optimize`：它要对全部标的算协方差矩阵，标的越多、lookback 越长越慢，是全链路成本大头。
- 其次是逐票 `factor-miner-vol_forecast`（N 只票 = N 次调用），持仓超过 8 只时建议只对权重最大的前 5 只逐票预测，其余合并评估。
- `factor-miner-regime_detect` 最便宜，只吃一条指数序列，先跑它拿上下文。

**重任务提醒**
- 本技能默认这三个工具都是同步返回、当场出结果，不要误用轮询。
- 但如果用户后续要求回测 / 模型训练 / 批量预测（例如 `factor-miner-factor_backtest`、`factor-miner-ml_train_rolling`、`factor-miner-ml_predict` 批量、`kronos-forecast_batch`），这些是异步任务：**先提交拿到 `job_id`，再用 `job_status`（job_id）轮询取结果，不要傻等、也不要重复提交**。轮询有结果就停，别死循环。

## 工具链

**第 0 步：向用户收集数据（必做，不要自己编）**
- 必需：持仓清单 —— 每只票的代码 + 权重（或市值/股数）。缺权重就用市值占比。
- 必需：K 线数据 `klines`。数据来源二选一，明确告诉用户：
  1. 让用户导出/粘贴各标的日 K（`[{date, close}, ...]`，按日期升序）；
  2. 若你已有行情源，可从行情接口取价格序列，整理成 `klines` 后传给工具。
- 组合优化还需要**共同交易日对齐**：日期不齐时以交集交易日对齐，并在报告里注明「实际用于计算的区间」。
- 拿不到数据就如实说缺什么，不要用假数据跑。

**第 1 步：确认市场状态（先跑，最便宜）**
- 调 `factor-miner-regime_detect`，参数：`klines`（传宽基指数日 K，如沪深300，或用户组合的等权合成收益序列）、`n_regimes`（默认 3 = 牛/震荡/熊；只想要牛熊就传 2）。
- 取回 `current_regime` 与 `regime_history`，作为后面所有结论的背景板。

**第 2 步：逐票波动率预测**
- 对每只票（深问时至少覆盖权重前 5 只）调 `factor-miner-vol_forecast`，参数：`klines`（该票日 K，含 high/low 更好，Parkinson 参考更准）、`horizon`（默认 5 个交易日，用户问「下周」「这个月」就按交易日折算）、`method`（默认 `auto`；用户想指定就 `ewma` 或 `garch`）。
- 记录 `current_vol` 与 `forecast` 序列，判断波动率是抬升还是回落。

**第 3 步：组合最优权重对比**
- 调 `factor-miner-portfolio_optimize`，参数：`symbols`（持仓代码数组）、`klines`（对象：`{symbol: [{date, close}, ...]}`，全部标的都要给）、`method`（默认 `hrp`，稳健；想对比可再跑 `equal` / `min_variance` / `mean_variance`）、`lookback`（默认 120 个交易日）。
- 拿到 `weights` 后，与用户**实际权重**做并列对比：差异越大，说明当前结构越偏离风险平价/最优解。

**第 4 步：算集中度（本地计算，不调工具）**
- 取用户实际权重降序，算前三大权重合计；同时给出最大单一权重、HHI（权重平方和）。
- 与 `factor-miner-portfolio_optimize` 返回的 `weights` 里前三大合计做对照。

## 输出格式

按以下小节输出，字段名保持稳定，便于 Agent 复用：

1. **体检结论**（2-3 句）：集中度处在什么水平、波动率在抬还是落、当前 regime 是什么。
2. **持仓集中度**
   - 前三大权重占比：xx.x%
   - 单一最大权重：xx.x%（标的）
   - HHI：x.xxx（<0.15 分散 / 0.15-0.25 中等 / >0.25 集中）
   - 与实际/优化权重对照表：标的 | 实际权重 | 优化权重 | 偏离
3. **波动率趋势**
   - 逐票表：标的 | 当前波动率 | horizon 内预测波动率 | 趋势（抬升/持平/回落）
   - 组合层面：加权平均波动率、波动率是否高于自身近 60 日均值
4. **市场状态与仓位区间**
   - 当前 regime：牛/震荡/熊（方法：rule 或 hmm，工具会返回 `method`）
   - 近 N 日 regime 切换次数（判断环境是否稳定）
   - 参考仓位区间：按 regime 给出统计意义上的区间（如熊市区间偏低、牛市偏高），并注明这是规则映射，不是买卖指令。
5. **风险提示清单**（纯统计事实）：同板块/高相关标的扎堆、单票权重超阈值、波动率抬升的标的等。
6. **数据与口径说明**：用于计算的交易日区间、`lookback`、`method`、缺失数据情况。

## 合规边界

- 只输出**统计计算结果**：权重、占比、波动率、regime、相关性、偏离度。
- **不输出**买入/卖出建议，不出现「建议减仓到 X%」「该买/该卖」「加仓」这类指令性表述；仓位区间只能表述为「统计意义上的参考区间」，不能表述为操作指令。
- **不输出**目标价、涨跌幅预测点位、收益承诺、胜率承诺。
- 涉及预测的部分（`factor-miner-vol_forecast` 的波动率预测、Kronos/ML 模型输出）必须标注「**模型输出，非承诺**」，并给出不确定性说明（如 GARCH/EWMA 的历史拟合局限）。
- 涉及 `factor-miner-regime_detect` 的 HMM 结果要注明是概率模型识别，regime 可能滞后转换。
- 不替用户做交易决策；用户要执行交易时，明确告知需走你自己的交易风控流程（本技能不执行交易）。

## 常见问题

1. **klines 日期不齐导致算不出来**：多标的协方差必须同交易日对齐。先取交集日期，再传给 `factor-miner-portfolio_optimize`；对齐后剩余样本不足 `lookback`（默认 120）时，主动调小 `lookback` 并说明，不要静默用短样本装作长期结果。
2. **标的太多跑得慢 / 成本高**：深问时先只对权重前 5 名跑 `factor-miner-vol_forecast`，组合优化仍用全持仓但可把 `lookback` 降到 60-90；不要对每只票都叠加多次 method 对比，一次主口径 + 一次对照即可。
3. **别把一次结果当永久结论**：波动率和最优权重随窗口滚动变化。报告里一定写清 `lookback` 与交易日区间；用户隔几天再问要重跑，不要直接复用旧数字。
