# K 线走势预测

## 何时使用

命中以下任意一种说法就调用本技能：

- 「这票未来几天怎么走？」
- 「帮我预测一下明天（下周）」
- 「明天会涨吗 / 还能拿吗？」
- 「这票短期怎么看，给我个方向」
- 「用模型跑一下未来 5 根 K 线」
- 「这只票最近走势怪，帮我看看模型怎么说」

**不适用**：需要买卖决策、目标价、仓位建议 → 本技能只给统计预测结果，不给交易建议。需要基本面/产业链逻辑 → 走研究员/知识图谱工具。

## 轻问 vs 深问（成本控制）

**轻问（1-2 个工具，秒级返回，优先默认走这条）**
- `kronos-model_info`() 确认模型已加载、可用
- `kronos-forecast_signal`(...) 拿方向 / 预期收益 / 置信度
- 适用：用户只想快速知道「短期偏多还是偏空」。回复 3-6 行即可。

**深问（完整链路 + 结构化报告）**
1. `kronos-model_info`() 确认模型与上下文上限
2. `kronos-forecast_signal`(pred_len=5) 主预测（方向一致性 × 离散度）
3. `kronos-forecast_kline`(pred_len=5) 拿逐根预测 OHLCV，观察路径形态（是否先跌后涨）
4. 批量多标的时 `kronos-forecast_batch` → 拿 job_id → 轮询
5. 可选叠加：`factor-miner-vol_forecast`（预测波动率）、`factor-miner-regime_detect`（市场状态）

**哪一步最贵**：
- `kronos-forecast_signal` 是**最贵**的一步 —— 它内部对同一输入跑 N 次独立采样（N = min(sample_count, 5)），耗时约为单次预测的 N 倍。**用户没明确要求时不要为了「更准」把 sample_count 拉满**。
- `kronos-forecast_batch` 是异步重任务，必须走 job_id + 轮询，不要同步傻等。
- `kronos-forecast_kline` 中等成本，深问时才调。

## 工具链

### 第 0 步：确认模型可用
```
kronos-model_info()
```
看 `loaded` / `max_context`（上限 512）/ device。若 `loaded=false` 且用户催得急，可直接调预测工具触发加载（首次加载较慢，要提前告知用户）。

### 第 1 步：准备 klines（必须先有数据）
`kronos-forecast_signal` 与 `kronos-forecast_kline` 都**必须由调用方提供 klines 数组**，本技能不会自己去取数据。数据来源二选一并明确告知用户：

- **用户提供**：让用户给代码（如 `sz002916`）+ 周期（日线/分钟线）。若用户只给了代码没给 K 线，需说明「我这边拿不到该标的 K 线，请贴一下或确认数据源」。
- **系统数据源**：从行情/盯盘/因子侧已有的 K 线读入后再传入，并在输出里注明数据来源与截止日期。

klines 格式（时间升序，`amount` 可省略）：
```json
[{"timestamps":"2026-01-02","open":0,"high":0,"low":0,"close":0,"volume":0}, ...]
```
约束：**lookback ≤ 512**；建议至少给 60 根以上，太短的序列（< 30 根）预测意义很弱，要在输出里提示。

### 第 2 步：主预测（方向 + 预期收益 + 置信度）
```
kronos-forecast_signal(
  klines = <上面的数组>,
  pred_len = 5,          // 建议 3-10 根，默认 5
  lookback = <可选，默认=klines 长度，上限 512>,
  sample_count = <可选，默认 5；这是成本旋钮，别乱拉满>,
  T = 1.0, top_p = 0.9   // 一般不用改
)
```
返回关键字段：`direction` / `expected_return_pct` / `confidence` / `risk_note`。
`confidence` 的算法含义 = 方向一致率 × 1/(1+收益 std%)，即**多次采样方向越一致、离散越小，置信度越高**。

### 第 3 步（仅深问）：看逐根路径
```
kronos-forecast_kline(
  klines = <同上>,
  pred_len = 5,
  lookback = <可选>,
  sample_count = <可选，默认 5>,
  future_timestamps = <可选：指定预测轴时间戳，长度 >= pred_len>
)
```
返回 `pred_len` 根预测 OHLCV + 交易视角 summary（方向/预期收益/预测波动率）。用来看「是先回踩再上，还是一路阴跌」这类路径形态 —— 但**路径本身依然是模型输出，不是承诺**。

### 第 4 步（仅多标的批量）：异步 + 轮询
```
kronos-forecast_batch(series_list = [{"id":"sz002916","klines":[...]}, ...], pred_len = 5)
  → 返回 job_id
kronos-job_status(job_id = "<job_id>")
  → status: queued / running / done / error；done 后读 result
```
**先提交拿 job_id，再用 job_status 轮询，不要傻等**。批量时逐项容错，单项失败不拖垮整批，结果里带 `error` 字段的项要单独说明。

### 用户需提供的输入清单
下单前先确认这三样，缺一项就先问：
1. **标的代码**（如 `sz002916`）
2. **周期**（日线 / 分钟线）与**数据区间**
3. **预测根数**（不指定就默认 5，按"未来几天"理解）

## 记忆回路（前查后记）

本技能的记忆维度是**模型历史预测与实际的偏差**（跟踪 Kronos 这只模型的可信度）：同一标的、同一周期、相近波动状态下，模型当时给出的 `direction` / `expected_return_pct` / `confidence`，事后对照真实 K 线到底走得如何。

| 时机 | 动作 | 工具 |
|---|---|---|
| 执行前 | 查该标的（或同板块、同周期）历史上 Kronos 的预测记录：跑了什么方向、当时置信度多少、事后有没有兑现；重点看「高置信却走反」和「低置信被当成方向用」两类旧账 | `causal-memory-search_causal`（query="Kronos 预测 <标的> <周期> 方向 预期收益 置信度 实际走势 偏差"） |
| 执行后 | 写入本次预测结论（**只写模型输出，不含任何买卖结论**）：标的/周期、`pred_len`、`direction`、`expected_return_pct`、`confidence`、`sample_count` 与采样一致率、数据截止日；结果字段先留空 | `causal-memory-record_decision`（decision="Kronos 预测 <标的> <周期> 未来 <pred_len> 根：<方向>，预期 <收益>，置信 <confidence>"，outcome="待验证"，context=<情境特征>） |
| 复检时 | 预测窗口（`pred_len` 对应的交易日）走完后，用**同一条 decision** 回填真实结果：实际涨跌幅、方向是否命中、偏差幅度，以及事后看当初那个置信度是否合理 | `causal-memory-record_decision`（同一条 decision，outcome="实际 <涨跌幅>，方向<命中/未命中>，偏差 <Δ>pct，原置信度<合理/高估/低估>"） |

写 `context` 时必带这些情境特征，否则将来匹配不到同类：标的与所属板块、周期（日线/分钟线）、klines 根数与数据截止日、当时市场状态（可先用 `factor-miner-regime_detect` 拿）与波动量级、`pred_len`、`sample_count`、当次 `confidence` 水平。

为什么这个记忆对用户有价值：Kronos 的 `confidence` 只是「采样一致率 × 离散度折扣」的**内部自洽度**，它衡量的是模型自己稳不稳，**不等于对真实行情的命中率** —— 高置信完全可能是"稳定地错"，低置信也可能碰巧对了。只有把每次预测的方向、置信度与事后真实走势成对存下来，才能在下次出口时回答「这只票、这类状态下，模型的置信度到底值不值得采信」，也让第 8 条置信度闸门有历史依据，而不是只报一个孤立数值。

## 输出格式

Agent 回复必须包含以下小节，字段名可中文化但不得缺项：

1. **标的与数据**：代码、周期、数据截止日期、使用的 K 线根数、数据来源。
2. **预测设置**：`pred_len`、`lookback`、`sample_count`（让用户知道成本花在哪）。
3. **方向**：`direction`（偏多 / 偏空 / 不明确）。
4. **预期收益**：`expected_return_pct`（区间量级表述，如"约 ±2% 量级"）。
5. **置信度**：`confidence` 数值 + **一句话解释来源**（"N 次采样中 X 次方向一致，收益离散度 Y"）。
6. **风险提示**：`risk_note` 原文要点。
7. **模型声明**（固定收尾，不可省略）：
   > 以上为 Kronos 模型输出的**概率性参考，非承诺**，不构成任何投资建议。
8. **置信度闸门**（强制）：
   - `confidence` 高 → 正常表述，但仍须带声明。
   - `confidence` 低（大致 < 0.4，具体以 `risk_note` 与采样一致率为准）→ **必须明写「方向不明确」**，不得用模糊话术暗示方向，也不得用低置信结果支撑任何偏向性结论。
9. **历史参照**（必填小节）：
   > 若检索到同类历史，写明「类似情境 N 次，其中 X 次 <本技能的判断维度> 正确」；
   > 无历史则写「首次记录此类情境，本次判断已存入记忆供将来对照」。

## 合规边界

- 只输出**统计计算结果**：方向、预期收益量级、置信度、预测波动率、路径形态。
- **不输出**：买入/卖出/加仓/减仓建议、目标价、止盈止损价位、仓位比例、收益承诺、胜率承诺、确定性措辞（"必涨""稳了""一定"）。
- 模型输出一律标注**「模型输出，非承诺」**；批量结果中失败的项如实说明，不补造数值。
- 不把预测结果包装成"信号"或"推荐"；若用户追问该不该买，明确回答这超出本技能边界，可转研究员/风控工具做逻辑与风险层面的分析。
- 不夸大外推能力：`pred_len` 越大越不可靠，超过 10 根要主动提示可靠性下降。

## 常见问题

1. **"为什么预测结果很平淡/没方向？"**
   `confidence` 是采样一致率乘上离散度折扣，横盘或高波动时本来就该低。这时正确回答是**「方向不明确」**，而不是硬凑一个方向 —— 硬凑方向是本技能最容易犯的错。

2. **"能不能预测 30 根？"**
   技术上 `pred_len ≥ 1` 都允许，但建议 3-10 根；越远误差越大。用户坚持要更长周期时，先说明可靠性衰减，再跑，并在输出里显著标注。

3. **"数据不够怎么办？"**
   klines 必须由调用方提供，太短（< 30 根）或缺失就如实说"数据不足，预测不可靠"，不要用少量数据硬跑出结论。`lookback ≤ 512`，超了会被裁。

4. **批量跑的时候卡住了？**
   `kronos-forecast_batch` 是异步任务：拿到 job_id 后用 `kronos-job_status` 轮询，`queued/running` 期间可以先做别的事或告知用户进度，不要阻塞式死等。
