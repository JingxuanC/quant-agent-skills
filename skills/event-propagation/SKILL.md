# 事件传导推演

## 何时使用

- 这个消息会传导到谁 / 影响哪些标的？
- 硅料涨价，下游谁受益谁受损？
- 这家公司出事，同一产业链的谁会跟着受冲击？
- 这个政策波及哪些板块？
- 上游涨价传到下游要几跳？衰减多少？
- 谁是这个事件的"最远端受益者"？

**边界（三个相邻技能的分工，务必分清，否则会互相误触发）：**

| 用户意图 | 归属技能 | 方法差异 |
|---|---|---|
| **"这件事会传导到谁"（事件驱动的即时传导）** | **本技能** | 知识图谱 BFS + LLM 语义推演 |
| "这条消息对**它自己**的股价冲击多大" | `event-impact` | 事件研究 CAR + t 检验 |
| "这两个板块**长期**谁带谁"（**无事件**） | `sector-linkage` | Granger / 传递熵 / PCMCI |
| "有什么消息？"（还不知道是哪个消息） | `news-radar` | 消息发现 |

> ⚠️ 关键区别：`sector-linkage` 回答的是**统计上的长期关系**（无事件、看历史序列）；本技能回答的是**给定事件后的传导路径**（有事件、看图谱与语义）。同一个"传导"词，方法完全不同 —— 用户说"传导"时若**没提具体事件**，交棒给 `sector-linkage`。

## 轻问 vs 深问（成本控制）

**轻问（默认，1–2 个工具）**：只想知道「大概会传到谁」。
- 调 `causal-chain-propagate_event`，传源头实体 + 初始冲击 + 图谱邻接表，得到沿图谱的 BFS 传导结果（跳数 + 衰减 + 方向符号）。
- 成本：纯本地计算，毫秒级。**默认走这条。**

**深问（2–3 个工具 + 结构化报告）**：用户要「完整的传导链 / 下游谁最受益」。
- 先 `causal-chain-propagate_event`（图谱路径）→ 再 `causal-chain-llm_propagate`（语义补充，用于**图谱没覆盖到但业务上明显相关**的标的）→ 必要时 `causal-chain-build_causal_links` 对传导链末端标的**算一次真实 CAR 验证**。
- 最贵的一步：`causal-chain-llm_propagate` —— 它要么现场调 LLM（几秒到十几秒），要么由 Agent 自己提供 `llm_response`。**它一次最多出 5 个标的**（工具内限制），别指望它做全产业链。
- 第二贵：`causal-chain-build_causal_links` —— 它需要对每个候选标的提供 K 线并逐个算事件研究。**候选标的超过 8 个就先筛再算。**

**批量/重任务**：本技能不做回测/训练。若用户要"对一批事件批量算传导"，那是 `batch-screening` 的职责。

## 工具链

### 第 0 步：锁定"事件 + 源头标的"（必须先解决）
本技能**不接受「硅料涨价会传到谁」这种没有源头标的的模糊输入**时直接开跑。先确认两件事：
1. **事件本身**：标题或描述（哪个事件）
2. **源头标的/实体**：冲击从哪个标的或板块开始传导（如 `sh600438` 通威股份，或实体名"硅料"）

缺源头就**追问**，不要自己挑一个开始推。若用户只说了一个事件没说源头，且该事件在库里（`news-get_events`）有 `symbols`，可用 `causal-chain-match_event_symbols` 先把事件匹配到候选源标的，**并明确告诉用户"我按 X 作为源头推演"**。

### 第 1 步：事件 → 标的匹配
- 工具：`causal-chain-match_event_symbols`
- 参数：`event_title`（必填）、`event_sectors`（逗号分隔板块，可空）、`existing_symbols`（事件已带标的时传入，会直接沿用）
- 返回：`symbols`（匹配到的标的数组）、`count`
- 读法：这是**关键词表 + 板块映射**的规则匹配，不是语义理解。匹配不到是常态，**如实说明"未匹配到标的"**，不要硬编。

### 第 2 步：沿知识图谱传播（核心）
- 工具：`causal-chain-propagate_event`
- 参数：
  - `source_entity`：源实体名或股票代码（含 `sh`/`sz` 也可）
  - `initial_impact`：初始冲击（如事件 CAR，**可为负**）
  - `edges_by_entity`：**知识图谱邻接表**，格式 `{实体: [{to_entity, relation_type, weight}]}`。**这是本技能的数据前提 —— 没有图谱就没有路径可推。**
  - `entity_name_of_stock`：`{股票代码: 实体名}` 映射，用于把代码解析成实体名、并把目标实体反查回股票代码
  - `max_hops`：最大跳数，默认 `3`。**超过 3 跳的传导衰减到基本没有信息量，不要为了"链更长"而调大。**
  - `decay_factor`：逐跳衰减，默认 `0.6`
  - `persist`：可选，`true` 则落库到 `kg_propagations`（便于 `get_propagations` 回看）
- 返回：`routes`（每条含 `target_entity`、`target_stock`、`impact`、`hop_count`、`path`、`decay`）、`count`、`max_hops`、`decay_factor`
- **⚠️ 方向语义的两道必查（本技能最关键的一步）：**
  1. **查关系是否被识别**：对 `edges_by_entity` 里出现的每个 `relation_type`，用 `causal-chain-relation_sign` 查它的 `known` 字段。
  2. **如果 `known=false` 的比例很高，必须在报告里明确披露**：这些关系全部走"同向"默认分支（符号 +1），**意味着传导方向的符号是不可信的**——只能看"传到了谁、衰减多少"，**不能看"是利好还是利空"**。
  > 实测：真实图谱里的关系类型常是 `AFFECTS` / `BELONGS_TO` / `CO_MENTIONED` 这类，而工具显式处理的是 `supplies_to` / `competes_with` / `invests_in` 等。**两者可能完全不相交**，此时方向全部退化。这是必须先查再报的原因。
  3. **`BELONGS_TO` 等归属关系会让 `max_hops=1` 就"传遍同板块"** —— 那不是产业链传导，只是归属关系。报告里要区分「板块内归属」与「产业链传导」，不要把前者说成后者。

### 第 3 步：LLM 语义传导（深问，补图谱的漏）
- 工具：`causal-chain-llm_propagate`
- 参数：`event_title`、`symbol`、`car`（小数，如 `0.025`）、`event_id`、`edges_by_entity`（用于 kg grounding）、以及二选一：
  - `return_prompt=true`：只拿构造好的 prompt，由 Agent 自己调 LLM（**推荐，可控**）
  - `llm_response`：自己拿到 LLM 返回后传进来解析（解析逻辑与真实调用完全一致）
  - `base_url` + `api_key`：让服务直接调（需 OpenAI 兼容端点）
- 返回：`routes`（含 `target_stock`、`name`、`impact`、`direction`、`reason`）、`kg_context`
- **用途与限制**：它的价值是**语义联想**（图谱没连上但业务上相关，如"同为大模型算力供应商"），最多 5 个标的，且**它排除源标的自身**。
- **必须标注**：LLM 输出的传导关系是**模型推断，不是实测关系**，报告里要与图谱路径分栏呈现，不得混为一谈。

### 第 4 步（可选）：对传导链末端做一次真实冲击验证
- 工具：`causal-chain-build_causal_links`
- 用途：图谱告诉你"传得到"，但**传到了是否真有价格反应是另一回事**。对末端标的提供 K 线（含基准），算一次真实 CAR，才能说"这条链在价格上确实有体现"。
- 参数要点：`events`（含 `event_time`，**必须落在 K 线日期范围内**，否则 CAR 静默返回 0）、`klines_by_symbol`、`bench_klines`、`car_window`（如 `[0,3]`）
- 读法：`direction` 若为 `insufficient_data`，说明**事件距今不足 5 个交易日**（方向判定需要事件后 5 根 K 线）。**此时没有方向结论，如实写出来，不要略过。**

### 第 5 步：合并输出（见下方契约）

## 记忆回路（前查后记）

本技能的记忆维度是 **传导链的兑现率**：我推演过的"会传导到 X"的路径，事后有多少**真的在价格上兑现**了。这是本技能最有价值的东西——**传导推演最容易自我说服**（图谱上确实连着、逻辑上确实通），只有事后对照才能知道哪类传导是真的、哪类只是"看起来连着"。

| 时机 | 动作 | 工具 |
|---|---|---|
| 执行前 | 查历史上对**同一源头实体或同一类事件**（如"上游涨价""出口管制""龙头出事"）报过的传导链及其事后兑现情况：哪类关系（supplies_to / invests_in / 同板块归属 / LLM 语义）的传导真的兑现了，哪类经常不兑现 | `causal-memory-search_causal`（query=`"事件 传导 产业链 兑现 衰减 跳数"`，task_tag=`event-propagation`） |
| 执行后 | 写入本次推演：`decision`=「`<事件>` 冲击 `<源标的>`，推演传导至 `hop1: <A,B>` / `hop2: <C>`，判定 `hop1` 最可能兑现的是 `<X>`」，`outcome` 固定先填「待验证」，`context` 写情境特征（事件类型、初始 impact、`max_hops`、`decay_factor`、**图谱关系类型构成与 `known=false` 的比例**、是否用了 LLM 语义补充、候选标的来源） | `causal-memory-record_decision`（decision=<本次推演>，outcome="待验证"，relation=`no_effect`（首次落账**必须** `no_effect`：结果未发生），task_tag=`event-propagation`，context=<情境特征>） |
| 复检时 | 5–20 个交易日后（或该传导链末端出现明显异动时）用**同一条 decision** 回填：推演的每个目标标的是否真的出现了方向一致的价格反应（用真实后续走势判断）；兑现的路径 relation=`enabled`/`caused`，未兑现的 `no_effect`。**特别要记"哪个 hop 开始断链"和"哪类关系类型最容易断"** —— 这是校准衰减系数 `decay_factor` 的唯一依据 | `causal-memory-record_decision`（同一条 decision，outcome=各跳兑现情况与断链位置，relation=兑现判定） |

为什么这个记忆对用户有价值：传导推演的诱惑在于**它永远能自圆其说**（图谱上确实有边、业务上确实相关），但市场的实际传导往往在第二跳就断了。只有把"这次推到第几跳、哪一跳没兑现"记下来，才能知道**对这个用户关注的那些产业链，`max_hops` 设几才不过度外推**，以及**哪些关系类型值得信、哪些只是纸面连接**。

## 输出格式

Agent 必须按下面小节输出，字段缺失就写「未取得」，不要编。

1. **结论一句话**：先给传导链主干，例如「`<事件>` 从 `<源标的>` 出发，1 跳传导至 `<A>`、`<B>`（方向：同向/反向），2 跳至 `<C>`；3 跳后衰减至噪声水平」。
2. **传导路径表（核心）**：

   | 跳数 | 目标标的/实体 | 关系类型 | 影响幅度 | 衰减系数 | 路径 | 方向可信度 |
   |---|---|---|---|---|---|---|
   | 1 | sh600438 | supplies_to | −0.0270 | 0.54 | 硅料 → 通威 | **高**（关系已识别） |
   | 2 | sh601012 | BELONGS_TO | +0.0180 | 0.36 | 硅料 → 光伏 → 隆基 | **低（归属关系，非传导）** |

   - 「方向可信度」列**必填**：由第 2 步的 `relation_sign.known` 判定。`known=false` 一律写「**低（关系未识别，方向取默认同向）**」。
   - 归属类关系（`BELONGS_TO` 等）要显式标注为"板块归属，不是产业链传导"。
3. **LLM 语义补充（单独分栏，仅深问）**：模型推断的关联标的 + 理由，**必须标注"模型推断，非实测关系"**，且不得与上表混排。
4. **价格验证（若做了第 4 步）**：末端标的的真实 CAR 与 `direction`；若 `direction=insufficient_data`，明确写「事件距今不足 5 个交易日，方向无法判定」。
5. **数据与方法声明（必写）**：`max_hops`、`decay_factor`、图谱边数与**关系类型构成**、`known=false` 的占比、是否使用 LLM 补充、`entity_name_of_stock` 的映射覆盖情况、是否有目标实体因无股票代码而未产出。
6. **置信度**：`高 / 中 / 低`，依据可核对的三点写：
   - **关系类型是否被工具识别**（`known=false` 占比高 → 直接「低」，因为方向不可信）；
   - 图谱是否覆盖该产业链（边稀疏 / 大量实体无股票代码映射 → 降级）；
   - 是否有价格验证互证（第 4 步算出显著 CAR → 升到「中/高」；没做验证 → 最高只能「中」）。
7. **不确定性与下一步**：可验证的建议，例如「补全该产业链的图谱边后重跑」「对 2 跳标的做一次 CAR 验证」「把 `max_hops` 降到 2 再看主干是否稳定」。

> **历史参照**（必填小节）：若检索到同类历史，写明「类似情境 N 次，其中 X 次 **推演的传导链在事后价格上真的兑现**（平均在第 N 跳断链）」；
> 无历史则写「首次记录此类情境，本次推演已存入记忆供将来对照」。

## 合规边界

- 只输出**传导路径的结构化描述**：跳数、目标标的、关系类型、衰减幅度、路径。
- **不输出**：买入/卖出建议、"受益标的"这类指向性表述（"受益"易被读成推荐，改为"该路径下影响为正"）、目标价、涨跌幅或收益承诺。
- **方向必须带可信度**：凡 `relation_sign.known=false` 的关系，**不得**给出"利好/利空"的结论，只能给方向符号并标注「方向不可信」。**这是本技能最容易出错的地方。**
- **图谱连接 ≠ 因果**：图谱上的边是**建模假设**（多由文档/关系抽取产生），不等价于真实传导。必须附固定话术：`以上为知识图谱上的路径推演：图中存在连接不等于真实传导，衰减系数为模型假设值而非实测值，路径未兑现是常见情形。`
- **LLM 输出必须标注**：`causal-chain-llm_propagate` 的结论一律加注「模型推断，非承诺」，不得作为结论依据、不得与图谱路径并列为同等证据。
- 若传导链末端接了预测模型（Kronos / ML 打分），必须加注：**模型输出，非承诺**。

## 常见问题

1. **没图谱就别硬推**：`propagate_event` 需要 `edges_by_entity`。若手上没有该产业链的图谱数据，**正确做法是明确说"缺少该产业链的图谱连接关系，无法做路径推演"并交棒给 `sector-linkage`（用价格序列做统计检验）**，而不是让 LLM 自由发挥编一条链出来。
2. **`known=false` 时方向是假的**：工具的 `relation_sign` 只显式处理少数几种关系（`supplies_to` / `upstream_of` / `competes_with` / `uses_component` / `buys_from` / `invests_in` / `belongs_to`），**其余一律返回 `+1`（同向）**。而真实图谱的关系类型常常完全不在这张表里 —— 此时**"正向影响"只是因为默认值，不代表利好**。先查 `relation_sign`，再决定敢不敢讲方向。
3. **`BELONGS_TO` 会把 `max_hops=1` 变成"同板块全员"**：归属关系一跳就把同板块所有票拉进来，看起来"传导面很广"，其实只是板块归属。报告里必须区分，并优先看 `supplies_to` / `invests_in` 这类真正的链条关系。
4. **事件日期不在 K 线范围内时 CAR 静默返回 0**：第 4 步验证时，`event_time` 必须在提供的 K 线日期区间内，否则 `compute_car` 的越界保护会返回 `0`（与设计一致，不报错）——**看起来像"没有影响"，实际是数据没对齐**。做验证前先核对日期。
5. **别把 `insufficient_data` 当结论**：`direction=insufficient_data` 表示**事件距今不足 5 个交易日**，方向判定需要事件后 5 根 K 线。这是设计限制，不是"没有影响"。遇到就如实说"方向暂无法判定"。
6. **衰减系数是假设值**：`decay_factor`（默认 0.6）是模型参数，`impact` 是**按假设衰减算出来的**，不是实测传导幅度。报告里不得把 `impact` 表述为"预计影响 X%"。唯一能校准它的办法就是记忆回路里那个"第几跳断链"。
