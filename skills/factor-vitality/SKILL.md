# 因子有效性检测

## 何时使用

- 「我这个因子还能用吗？」
- 「因子失效了吗 / 因子衰减了吗？」
- 「最近 IC 怎么样？IR 是多少？」
- 「这个因子我用了一年了，是不是该换了？」
- 「帮我看看 xx 因子最近还有没有区分度」
- 「因子分位收益还有单调性吗 / 换手高不高？」

## 轻问 vs 深问（成本控制）

| 档位 | 做什么 | 调用 | 成本 |
|---|---|---|---|
| 轻问 | 只要一个数：近期 IC 均值是多少、稳不稳 | 只调 `factor-miner-factor_recent_ic` | 低（纯 pandas，秒级，不需要市场 K 线） |
| 深问 | 要完整结论：IC 均值/IR + 分位收益单调性 + IC 序列与衰减 + 换手 | `factor-miner-factor_recent_ic` + `factor-miner-factor_tearsheet` | 中（tearsheet 需要用户提供**全部标的的 K 线**，数据量越大越慢） |

- **最贵的一步是 `factor-miner-factor_tearsheet`**：它要对每个标的、每个前向周期（默认 1/5/10 日）做分位分组与 IC 序列，输入数据量（标的数 × 天数）直接决定耗时。先用 1 个周期（如 periods=[5]）、标的缩到样本内，跑通再放大。
- 用户只丢一句「还能用吗」且没给数据时，先走轻问（让他给因子代码即可），不要一上来就要几十只票的 K 线。
- 如果确实要跑全市场批量回测（`factor-miner-factor_backtest`、`factor-miner-update_data` 等重任务），**先提交拿 job_id，再用 `factor-miner-job_status` 轮询**，不要阻塞傻等；轮询间隔 30-60 秒。

## 工具链

**第 0 步：向用户要两样东西**（缺一不可，不要自己脑补）
1. **因子源码**：符合挖掘器约定的 `factor.py`（读 `daily_pv.h5`、写 `result.h5`），对应 `code` 参数。
2. **K 线数据**（深问才需要）：`klines`，格式 `{"sh600519": [{"date": "2025-01-02", "close": 1520.0}, ...], ...}`，按日期升序，覆盖 IC 计算窗口 + 前向收益所需的额外天数（如算 5 日前向收益，末尾要多留 5 个交易日）。
   - 若用户拿不出 K 线，说明数据来源：从你这边的行情库或 qlib `cn_data` 导出，**不要用编造的价格**。

**第 1 步：近期 IC 快检** — 调 `factor-miner-factor_recent_ic`
- 参数：`code`（因子源码）、`name`（因子名，仅用于标识）、`lookback_days`（回看交易日，默认 60；看短线衰减用 20，看中期趋势用 120）
- 返回：`{ok, ic, days, error}` —— `ic` 是近 N 个交易日截面 Pearson IC 的均值
- 目的：先拿到「现在的」有效性水平，作为衰减判断的当期锚点

**第 2 步：分位收益 + IC 序列 + 换手** — 调 `factor-miner-factor_tearsheet`
- 参数：`factor_values`（形如 `[{"date": "...", "symbol": "...", "value": 0.83}, ...]`，即因子在每个标的每日的取值）、`klines`（同上）、`quantiles`（分位组数，默认 5）、`periods`（前向周期，默认 `[1,5,10]`）
- 返回：`quantile_returns`（分位收益）、`long_short`（多空价差）、`ic`（含 `mean` / `ir` / `series_summary` / `decay`）、`turnover`（换手）
- 目的：分位收益是否单调（单调=因子还有区分度，中间乱序=只剩噪声）、IC 序列的 `decay` 用来看衰减速度

**第 3 步（深问可选，做「对比历史」）** — 调 `factor-miner-factor_oos_check`
- 参数：`code`、`name`
- 返回：挖掘窗口 vs 纯样本外窗口的 IC / 年化 / 最大回撤 + 相对衰减 `decay`
- 目的：单看近期 IC 无法回答「衰减了没有」，必须有历史基线。拿它在 mining 窗口的 IC 与第 1 步的近期 IC 对比，才算真·衰减判断

**判定口径（固定阈值，写进报告）**
- `|IC| > 0.03`：有效；`|IC| < 0.02`：基本失效；0.02–0.03：临界观察
- `IR > 0.5`：稳定（IR = IC 均值 / IC 标准差）
- 分位收益单调递减/递增：加分；出现反转或 U 形：扣分
- 换手极高（分位组几乎全换）时，注意交易成本会吃掉纸面 IC

## 记忆回路（前查后记）

| 时机 | 动作 | 工具 |
|---|---|---|
| 执行前 | 查同一因子（或同族因子）此前的 IC 跟踪记录：上次体检的 |IC|/IR、当时的判定（有效/衰减中/失效）、以及是否已有「失效时点」结论 —— 避免这次判定与上次互相矛盾 | `causal-memory-search_causal`（query="<因子名/因子表达式> 近期 IC 均值 IR 有效性判定 失效时点 衰减"，task_tag="factor-vitality"） |
| 执行后 | 写下本次因子体检结论：因子名 + 回看窗口 + 当期 |IC|/IR + 判定档位（有效 / 衰减中 / 失效）+ 依据的历史基线来源 | `causal-memory-record_decision`（decision="<因子名> 在 lookback_days=<N>、periods=<...> 下 |IC|=<x>、IR=<y>，判定为<有效/衰减中/失效>"，outcome="待验证"，context="因子=<名>；窗口=<20/60/120>；标的池=<...>；市场 regime=<风格/极端行情>；基线=<mining 窗口 IC 来源>"） |
| 复检时 | 等 20–60 个交易日（或以用户下次问同一因子为触发）再体检一次，用同一条 decision 回填实际：后续窗口 IC 是否继续下滑、是否跌破 |IC|<0.02、判定是否命中 | `causal-memory-record_decision`（同一条 decision，outcome="<N> 个交易日后 |IC|=<x'>, IR=<y'>，实际<维持/衰减/失效>，与当时判定<一致/不一致>"） |

本技能的历史参照维度就是**同一因子的 IC/IR 时间序列与失效时点**：记忆里最该沉淀的不是单次 IC 数值，而是「某个因子在什么窗口、什么市场状态下开始衰减、多久后跌破 |IC|<0.02」。跨会话保留这条轨迹后，再次体检同一因子时可以直接做「当期 vs 上次」的同口径对照，不用再由用户翻旧报告；累积若干次回填后，还能回答「这个因子历史上平均失效周期是多少」这类单次计算给不出的问题，并对「是不是该换了」给出有历史证据的判定。

## 输出格式

Agent 必须按以下契约输出，缺项要显式写「数据不足，未能计算」，不得留空或猜测：

1. **结论行**：一句话定性 —— 有效 / 衰减中 / 失效（附当期 |IC| 与 IR）
2. **近期 IC 表**
   - 回看窗口（`lookback_days`）、有效交易日数 `days`
   - IC 均值、IR、IC 序列摘要
3. **衰减判断**（核心）
   - 当期 IC vs 历史/挖掘窗口 IC（来源要写明）
   - 相对衰减幅度（%），并映射为：维持 / 轻微衰减（<30%）/ 显著衰减（30%–60%）/ 失效（>60% 或 |IC|<0.02）
   - IC 序列 `decay` 形态（衰减快慢、是否断崖）
4. **分位收益与单调性**：各分位前向收益、多空价差、是否单调
5. **换手**：分位数换手率，并提示对成本的敏感度
6. **口径与局限**：数据区间、标的池、前向周期、缺失样本数
7. **可选**：如果调用了 `factor-miner-factor_oos_check`，附 mining / OOS 双窗对照

> **历史参照**（必填小节）：若检索到同类历史，写明「类似情境 N 次，其中 X 次 <本技能的判断维度> 正确」；
> 无历史则写「首次记录此类情境，本次判断已存入记忆供将来对照」。

## 合规边界

- **只输出统计计算结果**：IC、IR、分位收益、换手、衰减幅度等量化指标，以及「有效/衰减/失效」这类统计判定。
- **不输出**买入/卖出/加仓/减仓等交易建议，**不输出**目标价、预期收益率、收益承诺。
- 因子有效性 ≠ 策略可盈利：IC 只是截面相关性度量，不含交易成本、涨跌停、容量与拥挤度。必须在报告中写明这一限制，不要替用户下投资结论。
- 若使用 Kronos / ML 等预测模型的结果，必须标注「**模型输出，非承诺**」，且不得作为买卖依据。
- 不构成投资建议；最终决策由用户自行负责。

## 常见问题

1. **只给因子名、不给源码或因子值**：`factor_recent_ic` 需要 `code`（源码）、`tearsheet` 需要 `factor_values`（因子值序列），两者都不能靠名字反推。缺数据时先问用户，而不是用假数据跑一遍。
2. **klines 长度不够**：tearsheet 要算前向收益，K 线末尾必须比因子值多出 `max(periods)` 个交易日，否则最后几天的收益会是空值，IC 被系统性低估。另外各标的日期要对齐，缺失的标的会被丢掉。
3. **别把「IC 低」当成「因子写错了」**：先确认 `lookback_days` 与 `periods` 是否匹配用户想看的周期（短周期因子用 120 日回看会被稀释）；再确认是否踩到风格切换或极端行情区间。建议同时看 20/60/120 三个窗口，一致走低才是真衰减。
4. **单次 IC 有运气成分**：不要用一周的 IC 下结论；至少覆盖 60 个交易日，并看 IR（稳定性）而不只看均值。
