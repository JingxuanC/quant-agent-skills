# 板块联动分析

## 何时使用

- 这两个板块谁带谁？
- 板块之间到底是什么关系？
- A 涨了 B 会不会跟着涨？
- 这两条线的传导关系是什么，谁先动？
- 光模块和 PCB 是一伙的吗 / 有没有领先滞后？
- 我想知道这几只票里谁是"带头大哥"。

## 轻问 vs 深问（成本控制）

**轻问（默认，1 个工具）**：只想知道「A 和 B 谁领先谁」。
- 只调 `causal-granger_te`，传两个板块指数（或两只代表标的）的收益率序列，直接回双向 Granger 最优滞后 + p 值、双向传递熵、`lead_lag` 判定（`x_leads` / `y_leads` / `none`）。
- 成本：秒级同步返回，最便宜。

**深问（2–3 个工具 + 结构化报告）**：用户问「一篮子标的里谁带谁 / 整个传导链长什么样」。
- 先 `causal-learn_graph`（`method="pc"`）从多标的价格矩阵里发现全图因果边，再对最可疑的那条边用 `causal-granger_te` 单点复核，必要时加 `causal-pcmci_discover` 补滞后方向。
- 最贵的一步：`causal-learn_graph`（`method="pc"`）——它对**每一对变量**做条件独立检验，变量数 n 变多时是组合级增长；只想要 3–5 个板块就给 3–5 列，不要一次塞 30 只票。
- 第二贵：`causal-pcmci_discover`（装了 `tigramite` 走真 PCMCI，未装则降级为滞后偏相关筛选）。列数 × 滞后阶数决定开销，`max_lag` 每 +1 就多一轮检验。
- 最省的做法：先用 `causal-granger_te` 做两两粗筛，只把**显著的**那几个再拼成矩阵跑 `causal-learn_graph`。

**批量/重任务（回测/训练/大批量两两检验）**：
- 本技能三个工具本身是**同步返回**的，不要往一个调用里堆几十个序列或上千根高频 K 线，要**分片**调用（一次 3–5 列 / 一次两两一对）。

## 工具链

### 第 0 步：确认数据（必须先解决）
三个工具都**不接受空参数或「帮我查一下这两个板块」这种话**，必须把序列真的传进去（是数组，不是描述）。数据来源三选一：
1. **用户提供**：让他给日线 K 线，格式 `[{date:"2025-01-02", close:1234.5}, ...]`，两个板块各一份、**日期对齐、等长**。
2. **Agent 侧取数**：从本地行情库或 qlib `cn_data` 取板块指数或代表标的日线，取完转成上面的数组再调用（不要只说"取到了"，要把数组放进参数）。
3. **没数据就不要硬算**：明确回「需要两个板块各 ≥250 根日线，且日期对齐」，并说明用哪个口径（板块指数还是代表标的）。

**数据准备的两个硬规则：**
- **喂收益率，不是价格**：`causal-granger_te` 要的是**收益率序列**（价格序列是趋势项，直接跑会得到一堆伪显著）。把 `close` 转成对数收益 `ln(P_t / P_{t-1})`（或简单收益），两头对齐日期后再传。
- **样本量 ≥250 根**（约 1 年日线）；多变量因果发现（`causal-learn_graph` / `causal-pcmci_discover`）尤其吃样本——变量一多，条件独立检验的可用样本被迅速摊薄。**低于 120 根直接告知样本不足，不要出结论**；250–1200 根是舒服区间。序列越长越好，但别混入不同 regime 的十年老数据（见常见问题 3）。

### 第 1 步（轻问也做）：两两双向检验 —— 谁领先谁
- 工具：`causal-granger_te`
- 参数：
  - `x`：序列 X 的**收益率**数组（按时间升序）
  - `y`：序列 Y 的**收益率**数组（与 X 等长、日期对齐）
  - `max_lag`：最大滞后阶，默认 `5`。日线联动一般 `3`–`5` 够用；想抓更长周期的传导可给 `10`，但滞后越长、每一阶可用样本越少、越容易假显著。
- 返回（JSON）：`granger.x_causes_y`（含 `best_lag`、`p_value`、`p_by_lag`）、`granger.y_causes_x`（同结构）、`transfer_entropy.x_to_y` / `y_to_x`、`lead_lag`（`x_leads` / `y_leads` / `none`）。
- 关键：**必须双向都看**。只有单向显著 = 统计领先；双向都显著 = 更像同步共振（常见于同板块内 / 受同一宏观因子驱动），不要讲成"A 带 B"。

### 第 2 步（深问）：多标的全图 —— 谁和谁有线
- 工具：`causal-learn_graph`
- 参数：
  - `data`：表格对象 `{columns:["光模块","PCB","服务器",...], rows:[[r1_t1, r2_t1, ...], ...], dates:[...]}` —— `rows` 是**按时间升序的行**，每行对应同一天的多个**收益率**；`dates` 可选但建议给（便于报出区间）
  - `method`：`"pc"`（推荐，偏相关 + Fisher z 检验迭代删边）/ `"notears"`（简化版，未装 sklearn 会降级为相关性，此时结论更弱）
  - `alpha`：显著性水平，默认 `0.05`；想更严给 `0.01`
- 返回：`edges`（含 `from`、`to`、`weight`、`direction`）、`nodes`、`method`、`metrics`（`n_edges`、`sparsity`、`avg_weight`）。
- 读法：`edges` 是**无向骨架 + 统计方向**，PC 算法给出的方向不保证等价于物理因果；`sparsity` 太高说明几乎没边（可能样本不够或本就没有稳定联动），别硬解读。

### 第 3 步（深问，可选）：带滞后的方向复核
- 工具：`causal-pcmci_discover`
- 参数：
  - `data`：同上 `{columns, rows}`
  - `max_lag`：默认 `3`
  - `alpha`：默认 `0.05`
- 返回：`edges`（含 `from`、`to`、`lag`、`strength`、`p_value`）、`method`（`pcmci` 或降级为 `granger_fallback`）、`n`、`max_lag`、`alpha`。
- 用途：`lag` 是"领先几天"的量化表达，用来复核第 1 步的 `best_lag` 是否稳定。`method` 不是 `pcmci` 时，要在报告里写明是降级算法。

### 第 4 步：合并输出（见下方契约）
- 交叉验证原则：`causal-granger_te` 的 `lead_lag`、`causal-pcmci_discover` 的边方向、`causal-learn_graph` 的骨架方向，三者指向一致 → 证据较强；互相矛盾 → **明确写「证据冲突，方向未坐实」**，不要挑一个顺眼的报出来。

## 记忆回路（前查后记）

| 时机 | 动作 | 工具 |
|---|---|---|
| 执行前 | 查历史上对同一对板块（如 光模块 / PCB、算力 / 服务器）是否已经报过领先滞后关系，尤其是**同一方向上「统计领先」后来有没有真的兑现**（B 是否在 A 之后同向跟随），以及兑现失败时的共同原因（伪联动 / 共同上游 / regime 切换） | `causal-memory-search_causal`（query=`"+<板块A> <板块B> 领先滞后 联动 兑现"`，task_tag=`sector-linkage`） |
| 执行后 | 写入本次判定：`decision`=「`<A>` 统计领先 `<B>` 约 `best_lag` 天（Granger p=…，lead_lag=…）」或「`<A>`/`<B>` 双向不显著，判定同步共振/无稳定联动」，`outcome` 固定先填「待验证」，`context` 写情境特征（样本区间与根数、`max_lag`、`method`（`pc`/`notears`/`pcmci`/`granger_fallback`）、是否等长对齐、是否已把大盘作为条件变量） | `causal-memory-record_decision`（decision=<本次结论>，outcome="待验证"，relation=`enabled`（暂记；复检回填时改为 `caused` / `no_effect`），task_tag=`sector-linkage`，context=<情境特征>） |
| 复检时 | 当未来 `best_lag`（或 3–5 个交易日）窗口走完后回填真实结果：`<B>` 是否在 `<A>` 异动后同向跟随、滞后阶是否仍成立；兑现则 relation=`enabled`/`caused`，反向或不跟随则 relation=`no_effect` 或 `prevented`。**必须用与执行后同一条 `decision` 文本**，这样两笔记录构成可对照的「判定 → 兑现」闭环 | `causal-memory-record_decision`（同一条 decision，outcome=实际跟随结果与实测滞后，relation=兑现判定） |

本技能的历史参照维度只有一个：**过去报出的「统计领先」关系是否真的在后续行情里兑现成跟随**。Granger p 值和传递熵只能证明样本内存在信息流向，而市场结构会切换（同一上游因子、regime 断裂、流动性事件都可能让昨天的强边今天失效）——所以「这个判定上次对了没有」比「这次 p 值多小」更能校准用户的信任。对用户的价值在于：当同一个问题被反复问到（例如「光模块还带不带动 PCB」），报告能直接给出「类似情境 X 次、兑现 Y 次」的经验基线，而不是每次都让用户把统计显著误读成前瞻确定性。

## 输出格式

Agent 必须按下面小节输出，缺字段就写「未取得」，不要编。

1. **结论一句话**：先给判定，例如「光模块 → PCB：统计上光模块领先约 N 天（Granger p=…，传递熵 X→Y 大于 Y→X）」，或「未发现稳定领先关系（双向 p 值均不显著）」。
2. **方向与滞后表**（核心）：

   | 关系 | Granger p（最优滞后） | 传递熵 | 判定 | 证据强度 |
   |---|---|---|---|---|
   | A → B | p=…（lag=…） | 数值 | 领先 / 不显著 | 强 / 中 / 弱 |
   | B → A | p=…（lag=…） | 数值 | 领先 / 不显著 | 强 / 中 / 弱 |

   - 传递熵是**相对大小比较**（X→Y vs Y→X），没有绝对阈值；不要给它编一个"显著"标准。
3. **多标的全图（仅深问）**：`edges` 列表（from → to，weight，lag），`metrics.n_edges` / `sparsity`，以及一句话读图结论（比如"呈链式传导 A→B→C，而非 A 同时带动全桌"）。
4. **样本与方法声明（必写）**：每个标的的序列根数、样本区间、`max_lag`、`alpha`、`method`（`pc` / `notears` / `pcmci` / `granger_fallback`）、是否做了收益率转换、是否等长对齐。
5. **置信度**：`高 / 中 / 低`，依据可核对的三点写：
   - 样本是否 ≥250 根（<120 → 直接「低」）；
   - 双向是否一致、多个工具是否互证（互证 → 高，只有一个工具显著 → 中/低）；
   - `p_by_lag` 在各滞后阶上是否稳定（只在某一阶偶然显著 → 降级）。
6. **统计领先 ≠ 因果（必写，固定话术）**：`以上为收益率序列上的统计检验结果：Granger 检验的是"预测增量"，传递熵测的是"信息流向"，两者都只能说明统计领先/信息传导，不等于业务上的因果，也不代表未来会重复。共同上游因子（大盘、流动性、政策）会造成伪联动。`
7. **不确定性与下一步**：可验证的建议，例如补更长样本、把共同上游（大盘指数）作为条件变量再跑、换 `max_lag` 复核滞后阶稳定性。

> **历史参照**（必填小节）：若检索到同类历史，写明「类似情境 N 次，其中 X 次 **「统计领先」关系真实兑现为跟随**」；
> 无历史则写「首次记录此类情境，本次判断已存入记忆供将来对照」。

## 合规边界

- 只输出**统计计算结果**：Granger 最优滞后与 p 值、传递熵数值、因果图的边与权重、样本与方法口径。
- **不输出**：买入/卖出建议、目标价、涨跌幅或收益承诺、"A 涨了你就该买 B"这类指令式表述、杠杆/期货方向建议。
- **不做因果承诺**：禁止把 `lead_lag` 写成「A 必然带动 B」；一律表述为「统计领先 / 信息流向」，并附上第 6 条的固定免责话术。
- 传递熵、边权重都是相对量，**不得伪造显著性阈值**；`p_value` 只在 Granger 结果中如实引用。
- 降级算法（`notears` 降级为相关性、`pcmci` 降级为 `granger_fallback`）必须显式披露。
- 若本技能的报告后面接了预测模型（Kronos / ML 打分），必须加注：**模型输出，非承诺**，不得作为结论依据。

## 常见问题

1. **别喂价格，要喂收益率**：`causal-granger_te` 传 `close` 价格会得到几乎必然显著的伪结果（同趋势）。先转对数收益再传，两个序列必须**等长且日期对齐**，缺一天就扣一天，不要用前值硬填。
2. **多变量因果发现吃样本，不是吃算力**：`causal-learn_graph` / `causal-pcmci_discover` 的变量（列）越多，条件独立检验的可用样本越少，250 根配 10 个板块已经偏紧。宁可先用 `causal-granger_te` 两两粗筛，只把显著的几列拼成矩阵跑全图；一次塞 30 只票的结果基本都是噪音。
3. **跨越不同 regime 的长历史会污染结论**：把 2015 年杠杆牛和 2024 年的行情混在一条序列里，得到的"领先关系"往往是结构性断裂拼出来的。优先用近 1–2 年、同一 regime 下的数据；若用户坚持要长历史，就在报告里注明分区段并分段复核。
4. **双向都显著 ≠ 谁带谁**：同板块内的票、或同受大盘驱动的两个板块，经常双向显著。这时正确表述是「同步共振 / 共同上游驱动」，而不是"互相带动"，并建议把大盘指数作为条件变量再跑一次。
