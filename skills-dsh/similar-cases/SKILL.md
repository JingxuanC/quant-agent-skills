# 相似情境检索

## 何时使用

用户说出下面这类话（或意思相近），就调用本技能：

- 「我以前遇到过类似情况吗？」
- 「历史上这种情况我是怎么处理的？」
- 「有没有类似的案例，翻出来给我看看」
- 「我以前这种时候做对了吗？」
- 「这次跟上次那个是不是一回事？」
- 「帮我对照一下，这次和上次有什么不一样？」

判断标准：用户的诉求是**回看自己的经验**，而不是问「后市怎么看」或「该不该买」。如果用户要的是分析结论，那是别的技能；这里只做「历史情境 vs 当前情境」的对照。

## 核心机制

这是一个**私人经验检索器**，不是行情工具。它回答的永远是一个问题：**「过去在我身上，发生过像现在这样的事吗？当时我怎么做的？做对了吗？」**

三层工作原理：

**1. 记什么（谁在写）**
- 每次一个有分量的判断（买入、放弃、止损、加减仓、调参数、换策略），都要留下一条「决策 → 结果」因果边：`record_decision(decision, outcome, relation, task_tag, context)`。
- `context` 是关键——写清楚当时的环境（市场状态、板块、仓位、约束）。同样的 `task_tag` + `context` 会成为将来可对照的同源案例。写得越具体，将来检索越准。
- 结果还没出来时，`outcome` 先写「待验证」，**将来拿同一条 decision 再记一次真实结果**，把边补全。这是本技能能不能用起来的分水岭。
- 稳定不变的背景信息（偏好、风险参数、持仓特征、常做的板块）走 `record_fact`，不占用因果边。

**2. 什么时候查**
- 用户面对**当前情境、需要判断之前**——先查，再决定。不要让用户凭印象回忆。
- 准备做一笔交易/一次调仓/一次参数调整之前，查一次类似情境的结果。
- 定期（例如每周复盘）查一次 `prediction_report`，看自己的预测校准得怎么样。

**3. 什么时候回填（最重要）**
- 判断做出后，只要结果可观测，就回填。回填是记忆库区别于普通日志的唯一原因：**没有回填的日志只能翻，回填过的记忆能对照。**
- 回填时用同一条 decision 原文再记一次，让系统把「当时预期」和「真实结果」连起来。
- 若发现新结果和旧教训相反，用 `resolve_updates` 让系统判断旧记忆是否被推翻，而不是手动删。

## 工具链

### A. 查记忆（只读，随时调用）

**第 1 步 · 主检索**
- 工具：`search_causal`
- 参数：`query` = 当前情境的自然语言描述（把市场状态、板块、自己当时的处境写进去）；`task_tag` = 任务类别（如「加仓」「止损」「板块轮动」「参数调整」）；`limit` = 5～10
- 目的：把过去在相似情境下的「决策 + 结果」捞出来。

**第 2 步 · 兜底融合检索**
- 工具：`search_memory`
- 什么时候用：第 1 步结果太稀、或者你不确定该查事实还是查教训。它会同时搜「事实」和「因果」，融合排序。
- 想只看稳定背景（偏好/参数/持仓特征）时用 `search_facts`。

**第 3 步 · 找重复模式**
- 工具：`search_patterns`
- 参数：`query` = 与第 1 步同义的情境描述
- 目的：找出跨任务反复出现的模式——「相似」「重复」「矛盾」「改进」。这一层最有价值，因为它能告诉你：**这不是第一次，你已经在同一个坑里摔了三次。**

**第 4 步 · 重建完整叙事（按需）**
- 工具：`reconstruct_lesson`
- 参数：`query` = 情境主题；可选 `calibrate` = 2～3 让系统生成多份重建并报告一致性
- 什么时候用：前几步捞到的都是碎片、用户要一个完整故事、或者要看不同重建是否互相矛盾（矛盾说明这段记忆不可靠，要如实告知用户）。

**第 5 步 · 决策前对比（可选，用户正在两难时）**
- 工具：`counterfactual_query`（对比两个选项的历史结果，传 `context` 让同情境分支可比）
- 工具：`intervention_query`（行动前看类似动作历史上带来过什么后果）
- 注意：这两个工具的结论是**历史统计**，不是预测，也不是建议。

**第 6 步 · 复盘辅助（按需）**
- `trace_cause` / `trace_cause_chain`：从坏结果反推是哪次决策导致的，适合用户问「我这次亏在哪」。
- `prediction_report`：查看历史预测命中率，用于校准「该多信自己的直觉」。
- `causal_directory`：列出最近决策目录，用户想「过一遍我最近都干了什么」时用。
- `resolve_updates`：处理互相矛盾的旧记忆（先预览，确认后再落地）。

### B. 写记忆（会修改记忆库，先跟用户确认）

**第 7 步 · 记录新决策**
- 工具：`record_decision`
- 参数：`decision`（做了什么）、`outcome`（结果；未出结果写「待验证」）、`relation`（caused / enabled / prevented / no_effect）、`task_tag`（任务类别）、`context`（当时环境，越具体越好）、`confidence_source`（temporal / rule / llm_inferred / user_feedback）
- 关系怎么选：结果是决策直接造成的用 `caused`；决策让结果更容易发生用 `enabled`；决策挡住了坏结果用 `prevented`；看起来无关用 `no_effect`。

**第 8 步 · 记录稳定事实**
- 工具：`record_fact`：`key` / `value` / `scope`（user / session / agent）/ `confidence`
- 只在信息稳定时写（偏好、风控参数、持仓特征）。**不要拿它记决策结果**，那是第 7 步的事。

**第 9 步 · 回填结果**
- 工具：仍是 `record_decision`，用**同一条 decision 原文**、写入真实 `outcome`。
- 时机：结果可观测后尽快（如 T+5 看前瞻收益、平仓后、月度复盘时）。

**第 10 步 · 标记错误经验**
- 工具：`invalidate_decision`（`edge_id`, `reason`）
- 只在确认某条旧记忆是错的（数据错、归因错、情境不可比）时用。软失效——可审计，不物理删除。

## 输出格式

回答必须包含以下小节，缺一不可：

**1. 当前情境摘要**
一句话把用户现在面对的情况写成可对照的特征（市场状态 / 板块 / 仓位 / 约束）。

**2. 历史情境 vs 当前情境对照表**

| 维度 | 历史情境（日期/标的） | 当前情境 | 是否可比 |
|---|---|---|---|
| 市场状态 | | | ✅/⚠️/❌ |
| 板块/标的 | | | |
| 仓位与风险 | | | |
| 关键触发条件 | | | |

**3. 当时怎么判断的 · 结果如何**
逐条列：决策原文 → 关系类型 → 真实结果（或标注「结果未回填，仅供参考」）。有多个案例时按时间倒序。

**4. 可复用的点 / 需避免的点**
- ✅ 可复用：（上次有效的做法 + 相似度 + 依据）
- ⚠️ 需避免：（上次吃亏的做法 + 相似度 + 依据）
- 必须标注相似度，并说明哪几个维度不可比。

**5. 重复模式提示（如有）**
若 `search_patterns` 命中跨任务模式，明确写出：「这是第 N 次出现同一模式」。

**6. 记忆缺口**
如实说明：没有找到案例 / 结果尚未回填 / 样本太少不足以对照。不要为了给结论而硬凑。

**7. 免责声明**
固定一句：以上仅为历史记录与统计呈现，不构成买卖建议。

## 记忆价值

坚持用，会积累出四样外面买不到的东西：

1. **个人情境库**：不是「市场历史上如何」，而是「**我**在这种情境下如何」。同样的市场冲击，不同人应对方式完全不同，通用数据帮不上忙。
2. **失败模式清单**：哪些坑你已经摔过两次以上（`search_patterns` 会主动告诉你）。知道自己反复犯什么错，比多学一个指标有用得多。
3. **校准过的直觉**：`prediction_report` 会告诉你，你「感觉对」的时候实际命中率是多少。很多人对完之后发现自己的直觉被高估了，这是最值钱的一次认知更新。
4. **可回填的经验链**：每条决策从「待验证」变成有真实结果的记录，越用越厚。三个月后你面对新情境，系统能立刻给出三年前那次同类决策的真实结果。

一句话：**日志记得住发生过什么，记忆库才算得出你错在哪。**

## 合规边界

- 只呈现**历史记录与统计**，绝不输出买卖建议、目标价、仓位建议、收益承诺。
- 对照表里的「可复用 / 需避免」是**对过去记录的归纳**，措辞必须停留在「上次这个做法得到的结果是 X」，而不是「所以这次你也该这么做」。
- 不预测价格，不判断涨跌方向。
- 若用户追问「那我现在该买吗」，明确说明本技能只做经验检索，不给操作建议，建议其把结论交给风控/交易流程。
- 检索到的历史结果若样本量小（<3 例），必须显式标注「样本不足，参考价值有限」。

## 常见问题

**1. 为什么经常搜不到东西？**
绝大多数情况是**从没回填过结果**。初始只有一条条 `outcome = 待验证` 的边，检索时自然捞不到可用对照。解法：先把最近 5～10 笔判断的结果补上（第 9 步），检索质量会立刻不一样。

**2. `context` 写得太笼统怎么办？**
写「牛市」「加仓」这种词，将来会被一堆不相关案例命中，对照表全是噪声。要写到可区分：**什么市场状态、什么板块、什么仓位、什么触发条件**。`context` 的颗粒度直接决定这个技能的可用性。

**3. 搜出来的案例矛盾，该信哪个？**
不要手动二选一。用 `reconstruct_lesson` 加 `calibrate` 看一致性，再用 `resolve_updates` 让系统判断新证据是否推翻旧教训（先看预览再落地）。如果矛盾源于情境不可比，就在对照表里如实标注「不可比」，而不是强行归纳出规律。
